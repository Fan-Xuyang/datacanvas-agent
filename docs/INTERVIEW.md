# DataCanvas 工程实现与面试讨论

项目完成的是数据分析闭环：导入、字段理解、结构化规划、受约束执行、反馈修复、图表渲染、证据持久化与导出。真实供应商模型尚未联调；演示规划和模拟模型测试已验证。

## 三分钟演示

1. 选择内置 `sales.csv`，提问“按区域比较销售额，并生成图表”。可复核结果为华东 626000、华北 470000、西北 333000。
2. 展开指标口径，检查实际 SQL 与图表字段；展示执行事件、结果校验值与 Markdown 导出。
3. 改问“按月看销售额趋势”，展示不同结构化配置对应折线图。演示模式按关键词规划，不能将其描述为真实模型理解能力。
4. 上传自己的 CSV / XLSX，展示列名规范化与数据类型推断。

## 能解释的技术选择

| 问题 | 当前实现与取舍 |
| --- | --- |
| 如何体现 AI 原生前端？ | 模型输出 ChartSpec，Pydantic 限定 bar / line / table 和字段，React 使用固定组件渲染；不接受 formatter 或任意脚本。 |
| 为什么不是简单 Text-to-SQL？ | 有 Schema 和指标词典上下文、AST 约束、真实执行反馈修复、图表校验、证据结果持久化。 |
| 指标口径是否强制执行？ | 当前词典用于模型上下文与展示，并非完整指标语义引擎；不能保证模型一定遵循，需要核对 SQL。 |
| 为什么独立进程？ | 超时可终止，DuckDB 内存 256 MB、单线程、只读、禁止外部访问和扩展自动安装；它不等于系统级安全沙箱。 |
| 如何限制错误修复？ | 只对 SQL / 字段校验错误反馈，最多两次；每次计划和错误均留在事件表，超过预算失败。 |
| 刷新会不会丢失任务？ | 后台任务与 HTTP 连接独立。事件有单调序号，SSE 使用 Last-Event-ID 重放，前端按序号去重。 |
| 服务重启能否自动完成？ | 启动把遗留 running / queued 标为 interrupted，需要手动恢复；读取已存计划与结果继续。不是跨机器分布式执行。 |
| 怎么证明结果？ | 展示实际 SQL、数据集名称、返回表格和 SHA-256；哈希证明内容一致，不证明分析结论正确。 |

## 代码入口

- `app/data.py`：CSV / XLSX 导入、SQL AST 策略与进程调用。
- `app/query_worker.py`：受限制的 DuckDB 连接与取数。
- `app/agent.py`：规划、执行、修复和报告状态机。
- `shared/store.py`：任务状态与事件原子提交。
- `shared/api.py`：后台执行、取消、恢复、SSE 重放。
- `frontend/src/App.tsx`：ChartSpec 渲染、状态轨迹和证据展示。

## 可以继续深入的部分

当前仅支持单表、最多 20,000 行、有限 SELECT 函数，没有多租户或敏感字段脱敏。生产化可研究指标表达式编译、受控多表关系、任务队列和鉴权。不要把这些计划写成已完成功能。

## 面试中的数字回答

查询数值与独立 Python 汇总结果一致：100/100。实际工具流程 10/10 通过。回答时同时说明“本地、合成用例、规则模式、无模型”；不要只说 100% 准确率。评测细节见 [评测记录](EVALUATION.md)。
